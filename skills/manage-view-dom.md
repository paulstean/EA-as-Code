# Manage View DOM — AI Chat Selection Interaction

This skill explains how the AI Chat pane (in `visualiser.html`) can interact with the current selection state of the graph view. Use this when implementing or debugging chat-driven view interactions.

## Key Concepts

- **Single selection**: The graph uses vis-network with `multiselect: false`. Only one node can be selected at a time.
- **Selection is ephemeral**: `state.selectedNodeId` is not persisted across tabs or page reloads.
- **Chat is read-only**: The AI Chat server (`ea-chat-server.py`) proposes diagram changes via `CMD_REQUEST`, but the user must confirm them.

## Selection Architecture

### State

- `state.selectedNodeId` (line 530): The ID of the currently selected node, or `null`.
- `state.entryMap[nodeId]` (line 527): Maps every entry ID to its full data object.
- `state.network` (line 1600): The vis-network instance. Methods:
  - `state.network.selectNodes([id])` — programmatic selection.
  - `state.network.focus(id, { scale, animation })` — pan/zoom to a node.
  - `state.network.getPosition(id)` — get `{x, y}` coordinates.

### Functions

| Function | Line | Signature | Purpose |
|---|---|---|---|
| `showDetail(nodeId)` | 2516 | `showDetail(nodeId)` | Opens detail panel, sets `state.selectedNodeId`, renders fields + relationships. Returns nothing. |
| `closeDetail()` | 2619 | `closeDetail()` | Closes panel, clears `state.selectedNodeId`. |
| `refreshNodeLabel(nodeId)` | 695 | `refreshNodeLabel(nodeId)` | Rebuilds a node's label from `state.nodeFields[nodeId]`. |
| `addEntryToGraph(entryId)` | 1688 | `addEntryToGraph(entryId)` | Adds a node + edges to the graph. |
| `removeEntryFromGraph(entryId)` | 1707 | `removeEntryFromGraph(entryId)` | Removes a node + edges; closes detail if removed. |
| `executeCommand(action, target)` | 3561 | `executeCommand(action, target)` | Chat-driven add/remove. |

### Key Event Handlers

- `network.on('click', ...)` (line 1660): Calls `showDetail()` on node click, `closeDetail()` on background click.
- `network.on('hoverNode', ...)` (line 1613): Dims non-connected nodes, shows popover.
- `network.on('blurNode', ...)` (line 1645): Restores node colors, hides popover.

## AI Chat Protocol

The chat uses Server-Sent Events (SSE) from `POST /api/chat` on port 8765.

### SSE Event Types

| `data.type` | When | Payload | Visualiser Handler |
|---|---|---|---|
| `token` | Streaming response | `{ content: "..." }` | `appendStreamToken()` — renders incrementally |
| `cmd_request` | LLM proposes diagram change | `{ action, catalog, targets }` | `handleCmdRequest()` — shows Yes/No buttons |
| `command` | User approved | `{ action, target }` | `executeCommand()` — add/remove single entry |
| `done` | Response complete | `{}` | `addMessage('assistant', fullContent)` |
| `error` | Server/LLM error | `{ message: "..." }` | Shows error state |

### Text Tool Protocol (from LLM output)

The LLM inserts markers into its output that the server intercepts:

| Marker | Purpose | Server handler |
|---|---|---|
| `[[READ: CatalogName]]` | Load full catalog JSON | `read_catalog()` |
| `[[GET: entry-id]]` | Load single entry | `get_entry()` |
| `[[SEARCH: query]]` | Search entries by name/desc | `search_entries()` |
| `[[CMD_REQUEST: add|catalog|id1,id2,...]]` | Propose adding entries | `handle_cmd_request_marker()` |
| `[[CMD_REQUEST: remove|catalog|id1,id2,...]]` | Propose removing entries | `handle_cmd_request_marker()` |
| `[[APPROVE:CMD_REQUEST: ...]]` | User approved (generated by visualiser) | `handle_approve_marker()` |
| `[[REJECT:CMD_REQUEST]]` | User rejected (generated by visualiser) | `handle_reject_marker()` |

## How to Give the Chat Selection Context

The chat server's system prompt (`build_system_prompt()`, line 126) does NOT currently include selection info. To add selection context:

### Pattern 1: Inject selection into the chat API request

In `visualiser.html`, when building the chat request payload (around line 3275), include the current selection:

```javascript
var body = JSON.stringify({
  messages: chatMessages,
  model: chatModel,
  selection: state.selectedNodeId ? {
    id: state.selectedNodeId,
    entry: state.entryMap[state.selectedNodeId],
    position: state.network.getPosition(state.selectedNodeId),
    visibleIds: Array.from(state.visibleEntries)
  } : null
});
```

Then in `ea-chat-server.py`, extract `data.get("selection")` and inject it into the system prompt or as a context message:

```python
selection = data.get("selection")
if selection:
    sel = selection.get("entry", {})
    messages.insert(0, {
        "role": "user",
        "content": f"[Context: The user is viewing {sel.get('name')} ({sel.get('id')}) in the {sel.get('catalog', 'unknown')} catalog. Use this context to answer questions about it.]"
    })
```

### Pattern 2: Add a custom SSE event type

Add a new SSE event type to stream selection info to the chat:

```python
# In chat_loop(), before yielding tokens:
yield ("selection_context", selection)
```

```javascript
// In visualiser.html SSE event source:
if (data.type === 'selection_context') {
  // Store for later use
  state.chatSelectionContext = data;
}
```

### Pattern 3: Expose selection via a dedicated API endpoint

Add a `GET /api/selection` endpoint in `ea-chat-server.py` that returns the current selection (requires the visualiser to POST updates):

```python
def do_GET(self):
    if self.path == "/api/selection":
        self._send_json(current_selection)  # current_selection updated by visualiser via POST
```

## Chat-Driven View Actions (visualiser.html)

The visualiser already supports these actions from the chat via `executeCommand()`:

### Add entry to graph

```javascript
executeCommand('add', 'app-001');
// Calls addEntryToGraph('app-001'), checks sidebar checkbox, updates counts
```

### Remove entry from graph

```javascript
executeCommand('remove', 'app-001');
// Calls removeEntryFromGraph('app-001'), unchecks sidebar checkbox, updates counts
```

### Programmatically select and show details

```javascript
// Exposed as a helper for chat-driven actions:
function chatSelectNode(nodeId) {
  if (!state.entryMap[nodeId]) return;
  state.network.selectNodes([nodeId]);
  state.network.focus(nodeId, { scale: 1.5, animation: true });
  showDetail(nodeId);
  // Optionally send a follow-up message to the chat:
  var entry = state.entryMap[nodeId];
  sendFollowUpMessage('Now showing details for ' + entry.name + ' (' + nodeId + ').');
}
```

## Adding New Chat Capabilities

### Add a new SSE event type

1. In `ea-chat-server.py`, add a new yield type in `chat_loop()`:
   ```python
   yield ("custom_event", {"key": "value"})
   ```
2. In `visualiser.html`, add an `else if` branch in the SSE event handler (around line 3320):
   ```javascript
   } else if (data.type === 'custom_event') {
     // handle it
   }
   ```

### Add a new text tool marker

1. In `ea-chat-server.py`, add a handler function (like `handle_text_tool()` for `[[READ:]]`).
2. Add the detection + processing in `process_text_tools()`.
3. Add the early detection loop in `chat_loop()` (around line 414).
4. Update the system prompt in `build_system_prompt()` to document the new marker.

## Common Patterns

### Show a selection-dependent message

```javascript
// In the SSE handler, after a 'token' or 'done' event:
if (state.selectedNodeId) {
  var selected = state.entryMap[state.selectedNodeId];
  // The chat already knows what's selected from context, or you can add it as a follow-up
}
```

### Filter visible entries from chat context

```javascript
var visibleEntries = Array.from(state.visibleEntries).map(function(id) {
  return state.entryMap[id];
});
// Include in chat request body or system prompt
```

### Highlight a node based on chat suggestion

```javascript
function chatFocusEntry(entryId) {
  if (state.visibleEntries.has(entryId)) {
    state.network.selectNodes([entryId]);
    state.network.focus(entryId, { scale: 1.5, animation: true });
    showDetail(entryId);
  }
}
```
